## 1. New Feature — Maintenance Service Module (INSTRUCTIONS.md §39)

A fully independent module for tracking in-house device repair jobs. It shares **no** tables, auth, or routes with the storefront/admin `admin_users`, `products`, or `orders`. Auth is separate (`maintenance_users`), with its own JWT secrets and its own auth guard.

### Database (new)

- `migrations/002_maintenance_schema.sql`
  - `maintenance_users` — id, name, email (unique), password_hash, role (`admin` | `worker`), created_at
  - `maintenance_jobs` — id, worker_id (FK), device_type, part_type, cost_price, customer_price, percentage, `net_amount`, `net_profit` (both computed server-side), created_at
  - Indexes on `maintenance_jobs(worker_id)` and `maintenance_jobs(created_at)`
  - `net_amount` / `net_profit` are computed in the service layer and **never** trusted from client input

### Middleware (new)

- `src/middleware/maintenance-auth.middleware.ts` — `requireMaintenanceAuth` (separate guard, verifies maintenance JWT)
- `src/middleware/maintenance-rbac.middleware.ts` — `requireMaintenanceRole("admin" | "worker")`
- `src/middleware/rate-limit.middleware.ts` — added `maintenanceAuthRateLimiter`

### MVCS layers (new)

| Layer | Files |
|---|---|
| Routes | `src/routes/maintenance-auth.routes.ts`, `src/routes/maintenance-job.routes.ts` |
| Controllers | `src/controllers/maintenance-auth.controller.ts`, `src/controllers/maintenance-job.controller.ts` |
| Services | `src/services/maintenance-auth.service.ts`, `src/services/maintenance-job.service.ts` |
| Models | `src/models/maintenance-user.model.ts`, `src/models/maintenance-job.model.ts` |
| Validators | `src/validators/maintenance-auth.validator.ts`, `src/validators/maintenance-job.validator.ts` |

### Business rules enforced

- **Worker:** can create jobs (always assigned to themselves) and view/edit only their own job history — enforced in the service layer (`worker_id` scope), not just the UI.
- **Admin:** full access — create jobs for any worker, view/edit/delete all jobs, export.
- **Computed fields:** `net_amount = customer_price − cost_price`; `net_profit = net_amount − (net_amount × percentage ÷ 100)`, computed server-side at create/update time.
- **Monthly Excel export:** `GET /api/v1/maintenance/jobs/export?month=YYYY-MM` (admin only) streams an `.xlsx` workbook (via new dependency `exceljs`) with per-job rows plus a totals row.

### API surface

```
POST   /api/v1/maintenance/auth/login
POST   /api/v1/maintenance/auth/logout
POST   /api/v1/maintenance/auth/refresh
POST   /api/v1/maintenance/auth/reset-password

GET    /api/v1/maintenance/jobs            (worker: own; admin: all, optional ?month=YYYY-MM)
POST   /api/v1/maintenance/jobs            (worker/admin)
GET    /api/v1/maintenance/jobs/:id        (worker: own only; admin: any)
PATCH  /api/v1/maintenance/jobs/:id        (admin)
DELETE /api/v1/maintenance/jobs/:id        (admin)
GET    /api/v1/maintenance/jobs/export?month=YYYY-MM   (admin — .xlsx download)
```

## 2. New Feature — Search Endpoint (INSTRUCTIONS.md §17)

Dedicated storefront search endpoint (previously only `?q=` on `/products`).

- `src/routes/search.routes.ts`, `src/controllers/search.controller.ts`, `src/services/search.service.ts`, `src/validators/search.validator.ts`
- `src/models/product.model.ts` — added `search(q, limit, offset)` matching product **name, description, brand name, and category name** (active products only)
- Endpoint: `GET /api/v1/search?q=` → paginated products in the standard `{ data, error, meta }` envelope

## 3. Enhanced — Admin Analytics Overview (INSTRUCTIONS.md §13, §17)

`GET /api/v1/admin/analytics/overview` previously returned hardcoded zeros; now returns real metrics:

- `src/models/analytics.model.ts` (new) — revenue (this week/month), order volume (this week/month), top products, low-stock warnings, recent orders
- `src/services/analytics.service.ts` (new) — composes the overview
- `src/controllers/admin.controller.ts` (modified) — `overview()` now delegates to `analyticsService.overview()`
- Excludes cancelled/refunded orders from revenue/volume; low-stock threshold = 10 units
